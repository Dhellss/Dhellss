## Development Philosophy

Build things that solve a real problem, not things that only demo well.

Understand the layer below the one you are working in — the framework, the runtime, the operating system. It turns debugging into reasoning instead of guessing.

Write code the next person can read, including whoever I am six months from now.

Learn by building. Finish it, ship it, then find out what broke.
